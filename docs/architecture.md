# 架构、文件归属与修改边界

## 目标

项目札记提供本地的项目结构、目标、逻辑周日记录和交接展示。不同项目使用同一套存储格式与界面，项目特有的工作方式来自各自资料。新取得的软件不包含使用者的项目、学习计划或历史对话。

## 四类文件分别归谁

| 类型 | 位置 | 谁维护 | 是否进入源码仓库 |
| --- | --- | --- | --- |
| 软件工程 | 源码根目录 | 开发者 | 是：程序、通用文档、构建配置、测试和虚构测试资料 |
| 用户项目资料 | 所选资料根目录下的 `projects/<项目ID>/` | 用户授权的项目管理者或页面操作 | 否：结构、目标、角色规则、进度、报告及其备份 |
| 本机应用设置 | 系统应用设置目录 | 桌面应用 | 否：只保存所选资料位置等本机偏好，不保存项目进度 |
| 本地工作资料与运行产物 | 源码仓库外的本地目录 | 使用者或本地开发者 | 否：私人开发笔记、真实截图、旧配置和历史 Git 元数据；程序包通过发布产物单独交付 |

文件类型不决定归属。例如，字段说明和虚构 JSON 是工程内容，写在 README 里的真实学习进度仍属于用户资料。私人讨论不因发生在软件开发过程中就自动成为公开设计文档；公开文档只提炼通用设计与验证方法。

`正在使用文件/history/` 保存的是正式历史记录，仍属于用户项目资料；`备份资料/` 才是可以按需手动清理的副本。两者均不进入工程仓库。

## 模块与依赖方向

```text
原生窗口 desktop.py ──启动/结束──> 本机接口 local_server.py
       │                                  │
       └──显示 dist/ 界面 ──请求/响应───────┘
                                          │
                                    storage.py
                                          │
                                 外部用户资料目录

路径定位 app_paths.py 与平台适配 platform_support.py 为上述模块提供基础能力。
```

| 模块 | 负责 | 不在该模块实现的内容 |
| --- | --- | --- |
| `desktop.py` | 窗口、服务所有权、退出、原生剪贴板/保存对话框、资料目录切换 | 项目计划生成、进度判断、业务字段校验 |
| `local_server.py` | 本机 HTTP 边界、静态资源、接口解析和错误响应 | 教学流程、agent 调度、实际成果判定 |
| `storage.py` | 通用 JSON 校验、读写、原子替换、ETag、文件锁、按项目备份、满足条件后的周归档 | 特定用户的目标、角色或既有项目内容 |
| `app_paths.py` | 工程/打包资源、外部资料及本机偏好位置 | 把用户资料当作打包资源、写死用户目录 |
| `platform_support.py` | 操作系统文件锁和默认应用打开 | 各项目的运行环境和代码操作 |
| `dist/app.js` | 展示记录、表单交互、通过接口保存和读取 | 通过对话推断进度、自动更改规划、直接操作磁盘 |
| `dist/reading-plan.js` | 根据项目提供的角色与场景生成读取清单 | 固定所有项目的角色或写死实际文件位置 |
| `dist/help.js` | 面向操作者的通用使用说明 | 保存个人操作日志或把示例任务当成事实 |
| `dist/theme.js` | 首帧外观、日夜切换和偏好同步；桌面经原生桥保存，浏览器使用本地存储 | 写入项目 JSON、把外观选择当作项目内容 |
| `build_app.py`、`project_notes.spec` | 收集程序资源与运行依赖，生成平台运行包 | 收集外部项目、备份、个人配置或私人工作记录 |

## 三种规则各有作用范围

1. `AGENTS.md`：开发这个软件时的工程约定。
2. `记录读写说明.md`：任何被管理项目共用的字段、文件职责和保存协议。
3. 各项目 `project.json` 的 `constraints`、`collaboration`、`agentRoles`：该项目自己的技术边界、工作方式和角色职责。

软件可以提供管理与执行的操作示例，但不要求所有项目采用学习模式。软件的“不设登录”描述软件本身，不决定被管理项目的业务功能。

## 用户资料内部结构

下列名称只描述格式，不代表软件自带这些实际记录：

```text
资料根目录/
└── projects/<项目ID>/
    ├── 正在使用文件/
    │   ├── project.json
    │   ├── roadmap.json
    │   ├── current/weekNN.json
    │   ├── current/weekNN-handoff.json
    │   └── history/...
    └── 备份资料/
        └── 保存前备份/<时间戳>/...
```

项目自己的实际代码仓库、数据库和环境仍在其记录指定的位置；软件记录如何继续这些工作，不把外部项目代码吸收到本应用的源码中。

## 保存与更新

- 页面和外部工具使用同一套单文件接口，读取 ETag 后以 If-Match 保存；旧版本不能覆盖新内容。
- 存储层保存旧文件副本并原子替换目标文件，备份留在所属项目内部。程序不自动清理用户备份。
- 管理者判定实际状态并写入报告；存储层只检查格式与归档前置条件，不自行确认任务成果。
- 应用更新替换程序和公共说明，用户项目与本机选择的资料目录保持独立。字段迁移应明确范围，并在临时资料上先验证。
- 日夜外观属于本机应用设置。更新外观和选择资料目录均合并保存设置，不能相互覆盖；桌面首屏通过启动参数同步已选外观，macOS 窗口外观由平台适配层处理。

## 工程交接与验收

开发者应从 README、AGENTS.md 和本架构说明了解软件，不需要访问任何人的真实项目记录。验证时从干净的源码导出开始，使用空目录或测试临时目录；能够启动空项目、创建虚构项目、读写并构建，即可证明工程不依赖本机个人资料。

提交或发布前同时检查工作区文件和 Git 历史。仅在 `.gitignore` 排除用户文件不能消除已经进入历史的内容；旧站点配置、旧试用历史应在发布源之外保留。
